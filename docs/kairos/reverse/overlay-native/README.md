## Inferiert

Das vorhandene Datenmodell passt zum Bearbeiten eigenständiger Objekte auf einem eingefrorenen Bildschirm vor dem Flatten beim Export. Die voneinander getrennten Auswahl- und Szenenobjektzustände und die Move-/Resize-Callback-Typen sprechen für weitere Bearbeitung. Sie ersetzen keinen Nachweis der konkreten Eingabe-/Zustandsübergänge, insbesondere nicht nach schon angelegten Annotationen.

## Offen nach Abbruch der neuen Vertiefung

- Selector: Hit-Test → Drag/Resize → aktualisierte Eckpunkte → MouseRelease/Status → weiterhin verfügbare Toolbar.
- Rahmenänderung nach Annotationen: welche Status-/Lock-Bedingungen gelten und ob Objekte stehen bleiben, mitbewegt oder anders behandelt werden.
- Wrapper: erneute Auswahl → Move/Resize und Text-Properties → jeweilige Zustandsänderung → Undo/Redo desselben Objekts; Textinhalt-Undo gesondert.
- Toolbar: tatsächliche Registrierung der Werkzeugwerte und Verbindung von Buttons/Actions zum aktiven Werkzeug, nicht Icons als Funktionsbeweis.

Root führt die vollständige Abnahme durch. Dieser Bericht erhebt keinen Anspruch auf eine vollständige Analyse des Programms.

**Soll:** Eine private REA-6.4.0-/Ghidra-Sitzung für die zugelassene installierte Datei öffnen, den ersten Import wiederverwenden und ausschließlich die oben genannten Funktionen vertiefen. Die Root-MCP-Konfiguration blieb unangetastet. Ghidra 12.1.4 und JDK 21 wurden aus den ausdrücklich genannten vorhandenen Verzeichnissen gelesen; Laufzeit und Projekt lagen unter dem normalen freigegebenen Pfad `C:/Users/Axel_desktop/AppData/Local/KairosCapture/ReverseTools/overlay-contract-20261018`. Es gab keine Pfad-Aliase, Junctions, PATH-/MCP-/Installationsänderungen oder Admission-Umgehung.

**Ist:** `open_binary` bestätigte den erwarteten Target-Hash, `binary_session` meldete den Provider verfügbar. Die erste native Anfrage `procedure_pseudo_code({procedure:"0x140008690"})` lief von `14:20:16.110Z` bis `14:25:46.813Z` und scheiterte mit `provider_timeout`. Keine dritte native Anfrage wurde gestartet, kein Modell-/Providerwechsel und keine Reparatur am globalen Setup vorgenommen.
